# 程式架構說明

需求規格見 [SPEC.md](../SPEC.md)，開發守則見 [CLAUDE.md](../CLAUDE.md)。

## 1. 設計原則

- **核心與介面分離**：所有處理邏輯在 `tasks.py` 與各子套件，CLI（`cli.py`）與 GUI（`gui/`）都只呼叫核心。
- **服務可替換**：語音轉錄（STT）與文字整理處理（LLM）各有共同介面，新增服務只要實作介面並註冊。
- **不寫死模型與單價**：模型名稱、推理強度、單價放在 `assets/default_config.toml`、`assets/model_catalog.toml` 或使用者設定檔。
- **付費結果立即存檔**：每次雲端呼叫完成就寫入暫存，中斷後從中斷處繼續，不重複計費。
- **隱私**：日誌只記錄階段、時間、錯誤，不記錄逐字稿；金鑰存在 Windows 認證管理員。
- **Windows 專用**：路徑一律用 `pathlib`，指令碼用 PowerShell（相容 5.1 與 7）。

## 2. 處理流程

```
錄音檔
  │ ① 前處理 audio/preprocess.py：ffmpeg 轉 16kHz 單聲道 FLAC、音量正規化、剪出語音範圍
  ▼
  │ ② 語音轉錄 stt/：Azure／OpenAI／Soniox → SttResult（片段：起訖時間、講者、文字、語言）
  │    長錄音切段＋跨段講者串接（stt/chunk_merge.py）；時間碼加回語音範圍起點（tasks.shift_to_clip）
  ▼
  │ ③ 後處理 postprocess/：語言判定、OpenCC 臺灣繁體（zh_tw.py）、AI 臺灣在地化（localize.py）
  ▼
逐字稿文件 transcript_io.TranscriptDocument（也可匯入 txt／srt／docx／json）
  │ 使用者在「產出文件」分頁修正文字、講者命名、填會議資訊
  ▼
  │ ④ 刪除贅字 postprocess/filler.py：規則層＋AI 層＋「只刪不改」子序列驗證
  │ ⑤ 摘要 summarize/：依會議類型整理討論事項、結論、待辦、心智圖 → 依據片段驗證（validator.py）
  ▼
  │ ⑥ 輸出 render/：會議紀錄 .docx、逐字稿 .docx、心智圖 PNG／XMind
  ▼
輸出資料夾\{民國年月日}_{會議名稱}\
```

## 3. 目錄結構

```
quick-minutes/
├─ assets/                     # 隨程式發佈的資源（打包時整個收錄）

│  ├─ model_catalog.toml       # 模型選項、單價、各工作的建議模型
│  ├─ languages.toml           # 語言清單：代碼、STT 地區設定、偵測規則、贅字清單
│  ├─ term_map_tw.csv          # 中國用語 → 臺灣用語對照表
│  ├─ glossary/seed_道安業務.csv # 初始詞庫
│  ├─ icon.png                 # 程式圖示
│  └─ ffmpeg/ffmpeg.exe        # 打包時複製（不納入 git）
├─ src/meeting_scribe/          # 主程式（見第 4 節）
├─ tests/                      # pytest 測試（conftest.py 隔離使用者設定與金鑰）

```

## 4. 模組說明

### 4.1 核心

| 模組 | 說明 |
|---|---|
| `__main__.py` | 進入點：沒有參數開 GUI，有參數執行 CLI |
| `cli.py` | 命令列：`init-config`、`set-key`、`show-keys`、`transcribe`、`make-reference`、`benchmark`、`selftest` |
| `tasks.py` | CLI 與 GUI 共用的工作：`transcribe_audio`、`run_transcribe_job`、`localize_if_possible`、`clean_fillers`、`summarize_meeting`、`render_outputs`、`meeting_folder`、`run_benchmark` |
| `config.py` | 設定讀寫（出廠值＋使用者覆寫）、金鑰（keyring）、各資料夾位置 |
| `models.py` | pydantic 資料結構：`RawSegment`、`SttResult`、`Summary`、`MindNode` 等 |
| `transcript_io.py` | 逐字稿文件（`TranscriptDocument`、`MeetingInfo`）、從轉錄結果建立、匯入 txt／srt／docx／json |
| `checkpoint.py` | 中斷續跑的暫存：依錄音指紋與設定指紋區分，超過 30 天自動清除 |
| `usage.py` | 用量記錄（`record_stt`、`record_llm`）、費用估算、每月上限檢查 |
| `models_catalog.py` | 模型清單、單價、使用者新增或從服務查到的模型、官方「列出模型」API |
| `benchmark.py` | 引擎評估指標（CER、講者錯誤比例、詞庫命中率、語言判定）與報告 |
| `selftest.py` | 安裝後自我檢查（不需金鑰） |

### 4.2 子套件

| 子套件 | 模組 | 說明 |
|---|---|---|
| `audio/` | `preprocess.py` | 尋找 ffmpeg、轉檔、量測長度、切段匯出 |
| `stt/` | `base.py` | STT 介面、分段處理與續跑（`_run_chunked`）、重試 |
| | `azure_speech.py` | Azure AI Speech 快速轉錄（候選語言、語者辨識、詞彙清單） |
| | `openai_stt.py` | OpenAI 具語者辨識的轉錄（每 20 分鐘一段、重疊 30 秒） |
| | `soniox_stt.py` | Soniox 非同步轉錄（上傳 → 建立 → 輪詢 → 取回 → 刪除；已送出的工作可續取） |
| | `chunk_merge.py` | 切段規劃、以重疊區域串接跨段講者 |
| | `local_whisper.py` | 本機引擎（選用，尚未實作完整） |
| `postprocess/` | `lang_detect.py` | 片段語言判定（中、英、日、韓、混合） |
| | `zh_tw.py` | OpenCC s2twp 臺灣繁體轉換 |
| | `localize.py` | AI 臺灣繁體在地化（分批、驗證、逐批存檔） |
| | `filler.py` | 刪除贅字：規則層、AI 層、子序列驗證、逐批存檔 |
| | `glossary.py` | 詞庫讀取、提供給 STT 的詞彙 |
| `llm/` | `base.py` | LLM 介面：`complete_json(system, user, schema, task)`，task＝localize／filler／translate／summary |
| | `anthropic_llm.py` | Anthropic 官方 SDK：結構化輸出、effort、串流、伺服器端備援模型 |
| | `openai_llm.py` | OpenAI Chat Completions：JSON Schema 結構化輸出、reasoning_effort |
| `summarize/` | `prompts/*.txt` | 共通規則與三種會議類型（topic、qa、agenda）、分段合併的提示詞 |
| | `schema.py` | 摘要 JSON Schema |
| | `summarizer.py` | 呼叫 LLM、逐字稿過長時每 20 分鐘一段再合併、重試、逐段存檔 |
| | `validator.py` | 檢查每條結論的依據片段存在且相關，不通過標「待查證」 |
| `render/` | `docx_minutes.py` | 會議紀錄 .docx：公文版面、編號、Word 註解（依據時間）、待查證黃色標示、待辦表 |
| | `docx_transcript.py` | 逐字稿 .docx |
| | `mindmap_png.py` | Pillow 繪製心智圖 PNG |
| | `mindmap_xmind.py` | 直接產生 .xmind（zip＋JSON） |
| | `roc_date.py` | 民國年、星期、上午／下午時間格式 |
| `storage/` | `trash.py` | 移到資源回收筒（刪除詞庫用） |
| `gui/` | `main_window.py` | 主視窗：標頭、分頁、執行前檢查（金鑰、區域、ffmpeg、費用上限） |
| | `pages.py` | 「轉錄」「引擎評估」「詞庫」分頁 |
| | `document_page.py` | 「產出文件」分頁 |
| | `settings.py` | 「API 金鑰」分頁（語音轉錄、文字整理處理、費用） |
| | `audio_range.py` | 語音範圍拉桿與試聽播放器（QtMultimedia） |
| | `widgets.py` | 共用元件：檔案選擇、模型下拉選單、執行面板（背景執行、進度、經過時間、取消） |
| | `icon.py`、`shortcut.py` | 程式圖示、建立桌面捷徑 |

## 5. 設定與資料位置

| 位置 | 內容 |
|---|---|
| `assets/default_config.toml` | 出廠設定（隨程式發佈） |
| `%APPDATA%\MeetingScribe\config.toml` | 使用者設定（只寫入要覆寫的項目） |
| `%APPDATA%\MeetingScribe\glossary\` | 使用者詞庫 |
| Windows 認證管理員（服務名稱 `MeetingScribe`） | API 金鑰；開發時可用環境變數 `MEETINGSCRIBE_<名稱大寫>` 覆寫 |
| `%LOCALAPPDATA%\MeetingScribe\jobs\` | 工作檔：document.json、stt_raw.json、逐字稿草稿.txt、`_work\`（刪贅字、摘要的逐批暫存）、summary_{類型}.json |
| `%LOCALAPPDATA%\MeetingScribe\cache\{錄音指紋}\{引擎}_{設定指紋}\` | 轉錄續跑暫存：audio.flac、stt_result.json、chunks\、soniox_job_*.json、localize.json |
| `%LOCALAPPDATA%\MeetingScribe\usage.csv` | 用量與費用記錄 |
| `%LOCALAPPDATA%\MeetingScribe\logs\` | 日誌 |
| 輸出資料夾（預設 `文件\MeetingScribe\輸出`） | 成品，每場會議一個 `{民國年月日}_{會議名稱}` 資料夾 |

## 6. 擴充方式

| 要做的事 | 怎麼做 |
|---|---|
| 新增語音轉錄服務 | 在 `stt/` 實作 `base.py` 的介面，於 `stt/__init__.py` 註冊；`config.ENGINE_KEYS` 加金鑰名稱；呼叫完成時用 `usage.record_stt` 記錄用量 |
| 新增 LLM 服務 | 在 `llm/` 實作 `complete_json`，於 `llm/__init__.py` 的 `LLM_PROVIDERS` 註冊；用 `usage.record_llm` 記錄用量 |
| 新增 AI 步驟 | 透過 `complete_json(..., task=...)` 呼叫；**逐批存檔可續跑**（參考 `filler.py`、`localize.py`）；開始前檢查費用上限 |
| 換模型或單價 | 修改 `assets/model_catalog.toml`、`assets/default_config.toml`，不改程式碼 |
| 調整會議紀錄寫法 | 修改 `summarize/prompts/*.txt` |
| 新增語言 | 在 `assets/languages.toml` 加入代碼、STT 地區設定、偵測規則、贅字清單 |

## 7. 開發與測試

```powershell
.\scripts\setup.ps1                      # 建立 .venv、安裝相依套件
.\scripts\run_dev.ps1                    # 開發模式啟動（無參數＝GUI）
.\.venv\Scripts\python.exe -m pytest     # 全部測試
.\.venv\Scripts\python.exe -m ruff check src tests
```

- 測試透過 `tests/conftest.py` 把 `APPDATA`、`LOCALAPPDATA`、「文件」資料夾指到暫存目錄，並停用金鑰讀取，**不會讀寫使用者真正的設定、金鑰與輸出資料夾**。
- 呼叫雲端服務的部分以假的 HTTP 回應測試，不會產生費用。
- 每完成一個開發階段：執行全部測試、更新 README、建立 git commit（CLAUDE.md）。
